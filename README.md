# @colibri-terminal/sdk

> English version — [README.en.md](README.en.md).
>
> Путь автора — три стадии, от папки до каталога: [AUTHORING.md](AUTHORING.md).
>
> Правила публикации и отзыва: [policies/](policies/).

Типизированный клиент для API виджетов Colibri. Виджет — это веб-страница, которую терминал
открывает во встроенном WebView; этот пакет — удобный способ говорить с терминалом изнутри неё.

## Главное, что нужно понять сразу

Терминал кладёт «сырой» канал в `window.colibri` **до того, как выполнится любой код вашей
страницы**. Этот SDK — сахар поверх того объекта, а не второй контракт. Всё здесь необязательно:
виджет, который предпочитает `window.colibri.request("GET", "/exchanges")`, поддерживается ровно
так же и никогда не отстанет — оба пути идут через одну и ту же таблицу маршрутов.

Эта таблица не переписана руками: [`ROUTES`](colibri.js) сверяется с живыми маршрутами терминала
unit-тестом внутри самого терминала, так что SDK не может тихо разойтись с API, которое
оборачивает.

## Откуда берутся рыночные данные (прочтите до того, как писать скринер)

**Рыночные данные — забота вашего виджета.** Маршруты `markets.*` отдают то, что открыто у
ТЕРМИНАЛА: символ держится, пока его удерживает панель или вызывающая сторона, и отпускается,
когда становится не нужен. По устройству они привязаны к панелям и не могут ответить на скан
всей биржи. Для того, чем они являются, они полностью поддерживаются (стакан, который
пользователь и так смотрит; каталог площадок; история кластеров), и виджет вправе ими
пользоваться. Просто на них не стоит опирать основную функцию виджета.

Для сканирования, скрининга и вообще любых данных, которых у терминала ещё нет, подключайтесь к
бирже сами: перечислите хосты в списке `egress` своего манифеста и открывайте собственные
WebSocket'ы — из контекста страницы они работают напрямую, но только к хостам из этого списка:
терминал отдаёт ваш документ с `Content-Security-Policy: connect-src`, собранным из него, поэтому
сокет к необъявленному хосту бросает `SecurityError` уже при создании (терминал считает и пишет в
лог заблокированный хост — это видно в отчёте F12, туда и смотрите, если поток «молча» не
открывается). Хост без порта покрывает любой порт; `ws.okx.com:8443` — только 8443.

С REST сложнее, и это не теория: **KuCoin и Kraken Futures не отдают CORS-заголовки вообще**, так
что прочитать их из страницы нельзя никаким способом. Для таких запросов есть `colibri.net.fetch` —
его выполняет ТЕРМИНАЛ, по тем самым доменам, которые пользователь видел при выдаче разрешений:

```js
const r = await colibri.net.fetch("https://futures.kraken.com/derivatives/api/v3/tickers");
if (!r.ok) throw new Error(r.code);          // egress_denied · rate_limited · net_failed · …
const tickers = JSON.parse(r.body).tickers;  // body — это ТЕКСТ, разбираете вы
```

Правила, о которые проще всего споткнуться: только `https`, только GET и POST, хост должен быть в
`egress` (иначе `egress_denied`), редиректы НЕ выполняются — 3xx возвращается как есть, потому что
список разрешённых доменов, покрывающий только первый переход, ничего не разрешает. Есть и лимит
частоты на экземпляр (`rate_limited`).

Живые примеры обоих подходов — в `examples/`: «Радар ликвидаций» берёт биржевые WebSocket'ы
напрямую, «Фандинг-монитор» ходит в REST через хост.

Чего нет ни у кого, кроме терминала — и ради чего этот SDK, собственно, и нужен — это ваши
аккаунты: подключения, позиции, ордера, балансы, история закрытых сделок, торговля вашими
ключами, плюс панели, уведомления и ценовые алерты.

## Установка

Ни сборки, ни зависимостей. Либо положите два файла рядом со страницей:

```html
<script type="module">
  import colibri from "./colibri.js";
</script>
```

…либо, после публикации, `npm i @colibri-terminal/sdk`.

## Использование

```js
import colibri, { markets, panels, notifications, storage, stream, on } from "./colibri.js";

// Кто я и что мне можно? Доступно синхронно — без await и без события готовности.
const { widgetId, instanceId, surface, theme, grantedScopes } = colibri.handshake();

// Читаем состояние терминала.
const venues = await markets.exchanges();
const book = await markets.book("BinanceSpot", "BTCUSDT", { depth: 20 });

// Действуем в терминале.
await panels.add({ content: { exchange: "BinanceSpot", symbol: "ETHUSDT", views: ["orderbook"] }, activate: true });
await notifications.raise({ message: "Спред разошёлся больше 4 б.п.", severity: "warning" });

// Живые данные. Возвращает функцию отписки; сама переподписывается, если мост переключили.
const stop = stream.subscribe("trades", { exchange: "BinanceSpot", symbol: "BTCUSDT" }, (data) => {
  for (const t of data.trades) console.log(t.price, t.qty, t.isBuy);
});

// Долговременное состояние экземпляра — переживает перезапуск, стирается при удалении виджета.
await storage.set("layout", JSON.stringify({ sort: "volume" }));

// Тему терминала страница получает автоматически (CSS-переменные); подписывайтесь, только если
// нужно среагировать ещё и кодом.
on("theme", (e) => console.log("тема теперь", e.theme));
```

### Ошибки

Вызов резолвится телом ответа при успехе и **реджектится** `ColibriError` во всех остальных
случаях — забытая проверка не сможет выдать ошибку за данные. Разбирайте `code`, никогда не
`message`:

```js
try {
  await notifications.raise({ message: "" });
} catch (e) {
  if (e.code === "bridge_disabled") { /* пользователь выключил мост API в настройках */ }
  else if (e.code === "bad_request") { /* дело в вашем payload */ }
}
```

`bridge_disabled` (503) стоит обработать отдельно: пользователь может выключить мост API в
**Nest → «Настройки»**, и виджет останется *работающим*, но слепым к API. На обоих переходах
приходит событие `bridge`, так что можно показать деградированное состояние и восстановиться без
перезагрузки.

Ещё три, и все они про ограничения, которые поставил пользователь, а не про баг в вашем payload:

- `unauthorized` (401) — маршруту нужно разрешение, которого виджету не дали. Объявите его в
  манифесте, и оно станет частью того, на что пользователя спрашивают.
- `rate_limited` (429) — слишком много вызовов за последнюю минуту. Отступите и повторите; а если
  вы опрашиваете ради живых данных — подпишитесь на поток, для этого потоки и существуют.
- `budget_exceeded` (403) — ордер попал в разрешённое подключение, но вышел за лимит на ордер или
  за минуту, который пользователь задал вашему виджету. Покажите это пользователю; не повторяйте
  в цикле.

## Оформление

Хост отдаёт свою палитру в вашу страницу CSS-переменными (`--colibri-background`, `--colibri-buy`,
…) плюс `data-theme` и `data-colibri-lang` на `<html>`, и переотдаёт их при каждой смене темы,
цветов, размера шрифта или языка. Пользуйтесь переменными — и виджет выглядит родным без единой
строки кода.

## Версионирование

`apiVersion` растёт только по мажору: новые маршруты и новые необязательные поля его не двигают.
Объявите минимально нужную версию в `widget.json` как `minApiVersion` — терминал откажется
запускать виджет, которому нужен более новый API, вместо того чтобы упасть на середине первого
вызова. Мажор этого пакета следует за `apiVersion`.

## Как писать виджет

Виджет — это папка, в которой лежит `widget.json` и то, что собрала ваша сборка. Никакой
установки SDK и никакого инструментария, о котором терминалу нужно знать: если оно отдаёт HTML —
это может быть виджет.

```json
{
  "id": "my-widget",
  "name": "My Widget",
  "version": "1.0.0",
  "entry": "index.html",
  "icon": "icon.png",
  "surfaces": ["slot"],
  "permissions": ["marketData"],
  "minApiVersion": 1
}
```

`id` — DNS-метка в нижнем регистре, потому что это одновременно origin вашего виджета
(`https://<id>.widgets.colibri.internal`) и имя его папки. `permissions` — это то, на что
спрашивают пользователя: объявляйте только то, чем пользуетесь, потому что манифест, у которого
появилось новое разрешение, спросит заново.

Необязательное поле `icon` — путь к картинке внутри бандла (PNG, до 512 КБ): терминал показывает
её везде, где виджет виден — карточка каталога и листинг, список «Мои виджеты», вкладка «Виджеты»
в окне уведомлений, закладка в нижней строке, заголовок панели и окна, меню 🧩. Без иконки везде
рисуется значок 🧩. И про `surfaces`: только виджет, объявивший `"window"`, открывается отдельным
окном и может быть закреплён закладкой в нижней строке — slot-only виджет живёт только в панелях.

Дальше в терминале: **Nest → «Мои виджеты» → «Добавить виджет…» → «Разработка» → «Загрузить распакованный…»** и
выберите эту папку. Терминал отдаёт её **как есть, на месте** — ничего никуда не копируется, —
так что папка, которую вы правите, и есть та, из которой работает виджет. Поставить его в панель
можно кнопкой 🧩 на пустой панели.

### Цикл «правка — сохранение — результат»

Слежение включено по умолчанию. Сохраните файл — и виджет перезагрузится сам, обычно заметно
быстрее секунды. Указывайте загрузчику РЕЗУЛЬТАТ сборки (`dist/`), а не дерево исходников: бандл
ограничен 2000 файлами и 50 МБ, и `node_modules` пробивает оба — в отказе будет написано, какой
именно предел не сошёлся.

С бандлером весь цикл — это `vite build --watch` (или ваш аналог): он переписывает `dist/` на
каждое сохранение, а терминал это подхватывает. Проследите, чтобы `widget.json` попадал в вывод —
в Vite для этого достаточно положить его в `public/`.

Если вам привычнее HMR — можно и так: укажите в `entry` адрес `http://localhost:5173`, и терминал
откроет ваш dev-сервер напрямую. Такая форма принимается **только** для распакованного виджета и
только для буквальных `localhost` / `127.0.0.1`: это удобство для разработки, а не манифест,
который можно распространять. Тот же `connect-src` действует и на страницу с dev-сервера, причём
ваш dev-origin вписан в него как `'self'` вместе с портом — поэтому HMR-сокет Vite на порту самой
записи `entry` работает как есть, а вынесенный на другой порт (`server.hmr.port`) будет отклонён;
держите его на порту `entry`.

Кнопка `DevTools` в строке виджета (или в его меню ⚙) открывает Chromium DevTools по вашей
странице: консоль, сеть, элементы — всё как обычно. Для установленного виджета этой кнопки нет,
пока не включить «Инструменты разработчика для установленных виджетов».

### Что переживает перезагрузку

Перезагрузка заново открывает страницу, так что состояние в памяти теряется. Долговременная
половина — `storage`: он свой у каждого экземпляра, переживает перезапуски и обновления и
стирается при удалении виджета. Держите там всё, что пользователю было бы обидно вводить заново.

## Упаковка

«Упаковать для «Гнезда»» превращает папку в `.zip` плюс **хеш содержимого**, которым закрепляется
листинг.

Контракт — по **распакованному содержимому, а не по байтам архива**: распакуйте архив в папку,
посчитайте хеш — и должно получиться то же значение. Так сделано намеренно: значит, отправленный
вами хеш воспроизводится на любой машине любым архиватором, потому что ни временные метки, ни порядок
записей, ни уровень сжатия на него повлиять не могут.

Хеш — это SHA-256 по конкатенации, для каждого файла в порядковом порядке путей,
`UTF-8(относительный путь) ‖ 0x00 ‖ int64-LE(длина) ‖ SHA-256(байты)`. Пути через прямой слеш,
пустые папки не дают ничего, symlink'и отклоняются сразу — иначе ссылка могла бы протащить мимо
пина содержимое извне папки; по той же причине распаковщик не должен их создавать.

Манифест, у которого в `entry` стоит dev-сервер, упаковать нельзя: распространять там нечего.
