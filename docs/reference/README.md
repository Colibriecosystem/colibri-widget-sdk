# Справочник API виджетов

> English version — [README.en.md](README.en.md).

Справочник по SDK `colibri.js` и мосту `window.colibri`: каждая функция, каждое событие, каждое поле
манифеста и каждая переменная темы. Пишете первый виджет — начните с
[первого виджета](../getting-started.md); готовые решения частых задач — в [рецептах](../recipes.md).

## <a id="install"></a>Установка

SDK — это два файла: [`sdk/colibri.js`](../../sdk/colibri.js) и
[`sdk/colibri.d.ts`](../../sdk/colibri.d.ts). Ни сборки, ни зависимостей. В npm пакета нет:
`sdk/package.json` помечен как частный и нужен только этому репозиторию. Скопируйте оба файла в свой
проект:

- страница без сборки — рядом с `index.html`, импорт `./colibri.js`;
- проект на Vite или другом сборщике — в `src/lib/`, импорт `./lib/colibri.js`.

Шаблоны из [`starters/`](../../starters/) уже несут обе копии. Терминал кладёт в страницу только мост
`window.colibri`, а не SDK, поэтому SDK едет вместе с виджетом: в архиве виджета или на сервере
hosted-виджета.

```html
<script type="module">
  import { handshake, markets } from "./colibri.js";

  const { lang } = handshake();
  const venues = await markets.exchanges();
</script>
```

Можно брать функции по имени или весь SDK одним объектом — это одно и то же:

```js
import colibri, { markets, stream, on } from "./colibri.js";

const venues = await markets.exchanges();
const same = await colibri.markets.exchanges();
```

`colibri.d.ts` лежит рядом с `colibri.js`, и TypeScript находит типы сам; в обычном JS по ним
подсказывает редактор. Не правьте эти файлы у себя: новая версия SDK — это новые копии тех же двух
файлов, и всё своё удобнее держать в собственном модуле поверх них.

## <a id="bridge-vs-sdk"></a>Мост и SDK

Терминал кладёт «сырой» канал в `window.colibri` **до того, как выполнится любой код вашей
страницы**. SDK — сахар поверх этого объекта, а не второй контракт. Всё в нём необязательно: виджет,
который вызывает `window.colibri.request("GET", "/exchanges")` напрямую, поддерживается ровно так же
и никогда не отстанет — оба пути идут через одну таблицу маршрутов. Эта таблица не переписана руками:
[`ROUTES`](bridge.md#routes) сверяется с живыми маршрутами терминала тестом в самом терминале, так что
SDK не может тихо разойтись с API, которое оборачивает.

```js
import { markets } from "./colibri.js";

// SDK: тело ответа или исключение ColibriError.
const venues = await markets.exchanges();

// Мост напрямую: статус и тело при любом ответе, без исключений.
const raw = await window.colibri.request("GET", "/exchanges");
if (raw.status === 200) console.log(raw.body);
```

Чем отличаются два пути:

| | `window.colibri` | SDK |
| --- | --- | --- |
| Ответ на вызов | `{ status, body }` при любом статусе | тело при 2xx, иначе исключение [`ColibriError`](bridge.md#colibri-error) |
| Параметры запроса | готовая строка `query` | объект `params` |
| Версия формы ответа | только если передали `apiVersion` | [`API_VERSION`](bridge.md#api-version) в каждом вызове |
| `storage` | `{ ok, value, code }` | значение или `ColibriError` со статусом 0 |
| Поток | все кадры всех каналов в один обработчик; переподписка — ваша | обработчик на канал; переподписывается сам после сброса и после включения моста |
| События | `on` / `off` без типов данных | [`on()`](bridge.md#on) с типом данных и функцией отписки |

Мост есть в документах самого виджета и в его фреймах с тем же origin; фрейм чужого сайта моста не
получает. Вне терминала — например, когда страница открыта в обычном браузере — `window.colibri` нет,
и любая функция SDK бросает обычный `Error`. Проверьте `window.colibri` при старте, если страница
должна открываться и там. Описание самого объекта — тип
[`ColibriBridge`](bridge.md#types).

## <a id="conventions"></a>Общие правила

- **Числа на проводе — десятичные строки:** `"price": "64250.5"`, `"rate": "0.0001"` (это 0,01 %).
  Так не теряется ни один знак биржи. Переводите в число только там, где считаете; для показа берите
  строку как есть. Время — число миллисекунд Unix (`timeMs`, `nextFundingTimeMs`).
- **Идентификаторы долговечны.** `id` подключения, окна, вкладки, ячейки, окна графика и алерта,
  `clientOrderId` ордера и `instanceId` экземпляра переживают перезапуск терминала — их можно хранить
  в `storage`. Порядковый `index` окна или вкладки — не идентификатор: он сдвигается, когда что-то
  закрывают.
- **Вызов либо отдаёт тело, либо отказывает.** Каждая функция SDK резолвится телом ответа при 2xx и
  отклоняется [`ColibriError`](bridge.md#colibri-error) во всех остальных случаях. Разбирайте
  `e.code`, а не `e.message`. Исключение — `net.fetch`: он не бросает, а отвечает `{ ok, status, body,
  code }`.
- **Команда — не результат.** Вызов `trading.*` отвечает, когда команда принята в очередь; ответ
  биржи приходит в потоки `orders` и `positions`.
- **Что несёт кадр потока.** `book` — стакан целиком; `trades` — сделки с прошлого кадра, старые
  первыми; `funding` — текущая ставка; `positions`, `orders`, `balance` — весь набор каждый раз:
  заменяйте, а не сливайте; `notifications` и `signalLevels` — одно событие на кадр. Обработчик видит
  каждый кадр своего канала, поэтому сверяйте `data.symbol` или `data.connectionId`.
- **Подписка вместо опроса.** На виджет приходится 300 вызовов моста в минуту; подписка этот лимит не
  тратит.
- **Ответы растут.** В пределах одной версии API в ответы добавляются новые поля. Не падайте на
  незнакомом поле.

## <a id="errors"></a>Коды ошибок

Ошибка приходит одним из трёх путей:

- **исключение [`ColibriError`](bridge.md#colibri-error)** — от `request()` и всех функций областей;
  `status` похож на HTTP;
- **исключение `ColibriError` со статусом 0** — от `storage.*`; коды те же: `unauthorized`,
  `bad_request`, `bridge_disabled`, `quota_exceeded`, `internal`;
- **поле `code` в ответе `net.fetch`** при `ok: false` — `net.fetch` не бросает никогда.

Отказ в подписке на поток приходит кадром `{ type: "error", data: { code, message }, id }`; его видно
через `stream.onAny()`.

| Код | Статус | Что случилось | Что делать |
| --- | --- | --- | --- |
| `bridge_disabled` | 503 | Пользователь выключил API виджетов в настройках. Виджет работает, но каждый вызов, `storage` и `net.fetch` отвечают этим кодом, подписки потока сброшены. | Показать, что API выключен, и ждать событие [`bridge`](bridge.md#event-bridge) с `enabled: true`. `stream.subscribe` переподпишется сам. |
| `unauthorized` | 401 | У виджета нет разрешения, которое нужно маршруту: его не объявили, не выдали или пользователь его выключил. Ответ одинаков для любого недостающего разрешения. | Проверять [`hasScope()`](bridge.md#has-scope) до вызова, объявить разрешение в манифесте, слушать [`grants`](bridge.md#event-grants). См. [разрешения](#permissions). |
| `bad_request` | 400 | Неверный запрос: нет поля, не тот тип, недопустимое значение; повторная подписка на тот же канал; пустой или слишком длинный ключ `storage`; в `net.fetch` — не https, метод не GET и не POST, тело больше 256 КБ. | Исправить вызов. `message` объясняет, что не так, — читайте его глазами, а в коде решайте по `code`. |
| `not_found` | 404 | Нет такого маршрута — SDK новее терминала — или такой записи: закрытой сделки, алерта. | Для маршрута — потребовать нужную версию терминала через [`minColibriVersion`](manifest.md#manifest-min-colibri-version); для записи — перечитать список. |
| `unknown_connection`, `unknown_window`, `unknown_tab`, `unknown_slot`, `unknown_chart_window`, `unknown_panel` | 404 | Объекта с этим id больше нет: подключение удалено, вкладка закрыта, ячейка убрана. | Перечитать список (`connections.list()`, `workspace.get()`) и забыть сохранённый id. |
| `unavailable` | 404, 503 | Данных нет: у спотового рынка нет фандинга или он ещё не получен (404); часть терминала недоступна в этой сборке (503). | Не спрашивать фандинг у спота; иначе показать, что функция недоступна. |
| `not_ready` | 503 | Стакан ещё не ожил или подключение ещё не готово торговать. | Повторить через пару секунд; для стакана лучше подписаться на `book`. |
| `rate_limited` | 429 | Больше 300 вызовов моста за минуту; в `net.fetch` — больше 60 запросов в минуту; в потоке — больше 64 подписок сразу. | Отступить и повторить позже. Если опрашиваете ради живых данных — подпишитесь на поток. |
| `too_many_panels` | 429 | Виджет открыл слишком много панелей. | Не создавать ячейки в цикле: один вызов `workspace.addSlots()` создаёт до 16 ячеек. |
| `budget_exceeded` | 403 | Ордер вышел за лимит на один ордер или на число ордеров в минуту, который пользователь задал виджету. | Показать пользователю. Не повторять в цикле. |
| `trading_not_enabled` | 403 | Пользователь не разрешил виджету торговать через это подключение. | Показать, что этот счёт нужно разрешить виджету в его «Торговых подключениях». Не повторять. |
| `slot_occupied_by_widget` | 409 | В ячейке работает виджет; API не меняет и не очищает такую ячейку. | Выбрать другую ячейку. |
| `last_tab` | 409 | Попытка закрыть единственную вкладку главного окна. | Не закрывать её: у терминала не бывает главного окна без вкладок. |
| `unsupported_api_version` | 400 | Запрошена версия формы ответа, которой терминал не отдаёт. | Не передавать `apiVersion` в `RequestOptions`: SDK сам шлёт нужную. |
| `internal` | 500 | Сбой в терминале, а не в вашем запросе. | Повторить позже; если повторяется — напишите нам. |
| `no_slot` | 400 | `panels.self()` или `panels.siblings()` в окне: окно не стоит в сетке. Код ставит сам SDK, до терминала вызов не доходит. | Проверять `handshake().slotId` и слушать [`surface`](bridge.md#event-surface). |
| `quota_exceeded` | 0 | `storage` виджета заполнен: на виджет приходится 5 МБ. | Удалить ненужные ключи. Хранить настройки, а не данные. |
| `egress_denied` | 0 | `net.fetch`: хоста нет среди объявленных в [`egress`](manifest.md#manifest-egress) и разрешённых пользователем. | Добавить хост в `egress` — пользователя спросят заново. |
| `net_failed` | 0 | `net.fetch`: запрос не дошёл — нет соединения, ошибка DNS или TLS, отмена. | Повторить позже. |
| `net_timeout` | 0 | `net.fetch`: площадка не ответила за 15 секунд. | Повторить позже и реже. |
| `net_too_large` | ответ площадки | `net.fetch`: ответ больше 8 МБ. | Просить меньше: фильтр, страница, лимит. |

```js
import { connections, ColibriError } from "./colibri.js";

try {
  const { connections: list } = await connections.list();
  console.log(`подключений: ${list.length}`);
} catch (e) {
  if (e instanceof ColibriError && e.code === "unauthorized") console.log("нужно разрешение account:read");
  else throw e;
}
```

## <a id="permissions"></a>Разрешения

Разрешение открывает виджету часть API. Их семь:

| Разрешение | Что открывает | Каналы потока |
| --- | --- | --- |
| `marketData` | `markets.exchanges`, `symbols`, `book`, `clusters`, `funding` — рыночные данные, которые терминал уже держит | `book`, `trades`, `funding` |
| `account:read` | `connections.*` — подключения, позиции, ордера, балансы, история сделок. Только чтение | `positions`, `orders`, `balance` |
| `trading` | `trading.*` — выставить и отменить ордер, закрыть позиции | — |
| `panels` | `workspace.*` и устаревший `panels.*` — окна, вкладки, ячейки; `markets.orderbookSettings` и `patchOrderbookSettings` | — |
| `notifications` | `notifications.raise`, `signalLevels.signal` — уведомления и рыночные сигналы в терминал | `notifications` |
| `signalLevels` | `signalLevels.list`, `create`, `remove`, `removeBySymbol`, `clearTriggered` — ценовые алерты | `signalLevels` |
| `storage` | `storage.*` — своё хранилище ключ-значение. Его проверяет сам мост, а не таблица маршрутов | — |

Для каждого маршрута разрешение записано четвёртым элементом в [`ROUTES`](bridge.md#routes), для
каждого канала — в [`CHANNEL_SCOPES`](bridge.md#channel-scopes). Сетевые адреса и разрешения браузера
— не разрешения API: это отдельные поля манифеста, [`egress`](manifest.md#manifest-egress) и
[`browserPermissions`](manifest.md#manifest-browser-permissions).

Как виджет получает разрешение:

1. **Вы объявляете его** в [`permissions`](manifest.md#manifest-permissions) манифеста. Имя не из
   этих семи отклоняет манифест при установке (`manifest.invalid-permission`): опечатка не превратится
   тихо в «ничего не просит».
2. **Пользователь соглашается** в окне установки терминала — распакованный виджет тоже проходит это
   окно. Для `trading` он ещё подтверждает риск, выбирает счета и лимиты: по умолчанию $250 на ордер и
   12 ордеров в минуту, а снять лимиты можно только отдельным осознанным выбором. Если виджет
   просит `account:read` и адреса в `egress`, пользователь отдельно подтверждает, что данные счёта
   могут уйти по этим адресам.
3. **Новая версия, которая просит больше** — разрешение, адрес или разрешение браузера, — снова
   показывает окно согласия. Просить меньше можно без вопросов: лишнее отзывается сразу.
4. **Пользователь может выключить** любое выданное разрешение в «Моих виджетах», не удаляя виджет.
5. **Что у виджета сейчас** — `handshake().grantedScopes` и [`hasScope()`](bridge.md#has-scope): это
   объявленное, выданное и не выключенное. Когда набор меняется, приходит событие
   [`grants`](bridge.md#event-grants), и `grantedScopes` к этому моменту уже обновлён.
6. **Не объявили — не получите никогда**, даже если пользователь готов дать. Вызов без разрешения
   отвечает `401 unauthorized` — одинаково для любого недостающего разрешения.
7. **Терминал проверяет каждый вызов** по живому списку, а не по `handshake()`: отозванное
   разрешение перестаёт работать на следующем же вызове.

```js
import { hasScope, on, SCOPES } from "./colibri.js";

const render = () => {
  document.body.classList.toggle("no-account", !hasScope(SCOPES.accountRead));
};
render();
on("grants", render);
```

Как пережить отзыв разрешения на лету — [рецепт](../recipes.md#revoked-scope).

## <a id="versions"></a>Версии

Виджет имеет дело с несколькими номерами, и они значат разное:

| Номер | Где | Что значит |
| --- | --- | --- |
| `handshake().apiVersion` | терминал | Мажор контракта `window.colibri`, сейчас 1. Растёт только при несовместимом изменении: новые маршруты и новые необязательные поля его не двигают. |
| [`minApiVersion`](manifest.md#manifest-min-api-version) | манифест | Самый старый контракт, с которым работает виджет; по умолчанию 1. Терминал со старым контрактом не запустит такой виджет — вместо того чтобы тот упал посреди первого вызова. |
| [`minColibriVersion`](manifest.md#manifest-min-colibri-version) | манифест | Самая старая версия терминала, на которой работает виджет. Если виджету нужна возможность из Colibri 1.4, пишите её здесь, а не в `minApiVersion`. |
| [`API_VERSION`](bridge.md#api-version) | SDK | Версия формы ответа, сейчас 2; SDK шлёт её с каждым вызовом. |
| [`version`](manifest.md#manifest-version) | манифест | Номер версии самого виджета; правила — в [публикации](../publishing.md#release-version). |

**Формы ответов** версионируются отдельно, на каждый запрос: терминал читает `API_VERSION` из
конверта моста. Сегодня две формы есть только у устаревшего семейства `/app/panels`: v2 — одно
дерево `layout` на вкладку, v1 — старый плоский список ячеек, его получает запрос без версии.
**С терминала 1.4.0 v1 удалена, а версия в запросе не читается**; клиенту, который уже на v2 — то
есть этому SDK, — ничего менять не нужно. Новый код пишите на [`workspace`](layout.md#workspace-get),
а не на `panels`.
