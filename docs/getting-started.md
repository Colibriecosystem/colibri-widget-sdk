# Первый виджет: от шаблона до каталога

> English version — [getting-started.en.md](getting-started.en.md).

За полчаса вы пройдёте весь путь автора: создадите виджет из шаблона **«Простой»**, поправите его с
горячей перезагрузкой, выпустите версию 1.0.0 по ссылке, а следующей версией попросите место в
каталоге Nest. Node.js и сборка не нужны: шаблон — одна HTML-страница.

Каждый шаг говорит, куда нажать и что вы должны увидеть. Подробно о каждом экране вкладки
**«Автор»** — в [publishing.md](publishing.md).

## <a id="before-you-start"></a>Что понадобится

- **Colibri с шаблонами.** На вкладке **«Автор»** окна Nest, в разделе **«Код»** виджета, должна
  быть карточка **«Из шаблона»**. Если её нет, обновите терминал.
- **Текстовый редактор.** Подойдёт любой. VS Code подсказывает по типам API: файл `colibri.d.ts`
  лежит рядом с кодом виджета.
- **Интернет.** Терминал скачивает шаблон из релиза этого репозитория на GitHub и отправляет версии
  в Nest.
- **20–30 минут.** Node.js для этого пути не нужен.

## <a id="become-author"></a>1. Станьте автором

Нажмите **«Nest»** в верхней панели терминала и откройте вкладку **«Автор»**. Слева — карточка
**«Как устроена публикация»**: пять шагов, по которым идёт и эта страница. Справа — форма
**«Стать автором»**.

Входа и пароля нет. Nest выдаёт **ключ автора**: он и есть ваша личность в Nest, и он принадлежит
этому ПК.

1. **«Имя в каталоге»** — им подписан каждый ваш виджет. Обязательно.
2. **«Эл. почта»** — тоже обязательно, но её видят только модераторы Nest: по ней с вами свяжутся о
   ваших виджетах.
3. **«Канал на YouTube»**, **«Канал в Telegram»**, **«Telegram для связи»** и
   **«Ссылка на исходный код»** — по желанию, их можно заполнить позже.
4. Нажмите **«Стать автором»**.

Вкладка превратится в рабочее место автора, а сверху появится карточка **«Ключ автора на этом ПК»**.
Nest показывает ключ один раз: нажмите **«Копировать»** и сохраните его в менеджере паролей. Тот, у
кого окажется ключ, сможет публиковать от вашего имени, — храните его как пароль. Сразу нажмите и
**«Настроить восстановление»**: код восстановления вернёт доступ, если этот ПК пропадёт. Затем
**«Я сохранил ключ»**.

Профиль автора и что в нём видно — [publishing.md#author](publishing.md#author). Как работать с
другого ПК и как восстановить ключ — [publishing.md#author-key](publishing.md#author-key).

## <a id="new-widget"></a>2. Создайте виджет

В строке автора наверху нажмите **«Новый виджет»**. Диалог спрашивает только **«Название»** —
например, «Мой спред». Категорию и описание можно ввести здесь же, раскрыв
**«Заполнить сейчас (необязательно)»**, или позже, в листинге. Нажмите **«Создать»**.

Откроется страница виджета с разделами **«Обзор»**, **«Версии»**, **«Листинг»**, **«Код»**,
**«Доступ»** и **«Статистика»**. Рядом с **«ID»** написано **«появится, когда будет связан код»**:
ID виджета — это поле `id` в его `widget.json`, и черновик берёт его у кода, который вы с ним
свяжете. В этом руководстве ID впишет шаблон. Правила ID — в
[publishing.md#widget-id](publishing.md#widget-id).

В разделе **«Обзор»** карточка **«ЧТО ДАЛЬШЕ»** уже говорит, что делать: **«Свяжите с кодом»**,
кнопка **«Связать код»**.

## <a id="code"></a>3. Код: три способа

Откройте раздел **«Код»**. В нём три карточки — три способа дать виджету код. Версии потом
выпускаются из того, что здесь связано.

**«Папка с проектом»** — папка с `widget.json`, которую вы сделали сами или взяли из SDK. Черновик
возьмёт ID из этого `widget.json`, а терминал будет отдавать папку на месте, с горячей
перезагрузкой. Подробнее — [ниже](#own-folder).

**«Из шаблона»** — терминал сам создаст проект из одного из четырёх шаблонов SDK, впишет в него ID
виджета и сразу его запустит. Этот путь — следующий шаг руководства.

**«Адрес сайта (hosted)»** — для веб-приложения, которое уже работает по https: терминал соберёт
манифест сам, а код останется на вашем сервере. Подробнее — [ниже](#hosted).

## <a id="from-template"></a>4. Проект из простого шаблона

1. В карточке **«Из шаблона»** нажмите **«Выбрать шаблон…»**. Откроется
   **«Новый проект из шаблона»**, и терминал загрузит список шаблонов из последнего релиза SDK.
2. Выберите **«Простой»** — плитку с пометкой **«без сборки»**.
3. В поле **«ID»** терминал предложил ID по названию, латиницей. Поправьте его, если хотите,
   например на `my-spread`: строчные латинские буквы, цифры и дефисы, до 40 символов. Пока у виджета
   нет ни одной версии, ID можно менять.
4. **«Где создать»** — родительская папка; по умолчанию это `ColibriWidgets` в папке пользователя.
   **«Изменить…»** выберет другую. Под полем видно, где появится проект: `<папка>\<ID>`.
5. Нажмите **«Создать проект»**.

Под кнопкой видно, что делает терминал: скачивает шаблон и сверяет его SHA-256 с релизом, вписывает
ID во все `widget.json` проекта, меняет ID черновика в Nest на этот и загружает папку `widget/` с
горячей перезагрузкой. Как устроены шаблоны — [starters/README.md](../starters/README.md).

Терминал загружает подпапку `widget/`, а не корень проекта: всё, что он загружает, он хеширует и
упаковывает в версию, а README и `.git` из корня виджету не нужны.

Если список шаблонов не загрузился, проверьте сеть или прокси и нажмите **«Повторить»**. Или
скачайте шаблон кнопкой **«Шаблоны на GitHub»**, впишите ID в `widget/widget.json` сами и свяжите
папку `widget/` как [свою папку](#own-folder).

## <a id="first-run"></a>5. Первый запуск

Сразу после создания терминал спросит разрешения — так же, как спросит каждого пользователя при
установке. Окно перечисляет, что просит виджет: рыночные данные и своё хранилище (`marketData` и
`storage` в `widget.json`). Нажмите **«Разрешить»**.

Что вы увидите:

- **Окно виджета.** Шаблон объявляет поверхность `window`, поэтому терминал открывает новый проект в
  отдельном окне: выбор биржи, поле с монетой `BTCUSDT` и живые бид, аск и последняя сделка. Закрыли
  окно — в разделе **«Код»** есть **«Открыть в окне»**.
- **Код.** В разделе **«Код»** — **«Связанная папка»** с путём к `…\my-spread\widget` и включённым
  переключателем **«Горячая перезагрузка»**; рядом с **«ID»** в заголовке — `my-spread`. Над
  страницей — строка о том, что проект создан и уже работает.
- **Список виджетов.** В Nest → **«Мои виджеты»** тот же виджет с пометкой **«DEV»**: это ваша
  папка, а не установка из Nest.

Чтобы поставить виджет в раскладку, в пустом блоке нажмите 🧩 в правом верхнем углу (подсказка
**«Поместить виджет в этот блок»**) и выберите свой виджет.

## <a id="hot-reload"></a>6. Правка с горячей перезагрузкой

Откройте `widget/index.html` в редакторе: кнопка **«Открыть папку»** в разделе **«Код»** откроет
папку `widget/`. Весь виджет — этот файл. Добавим спред — разницу между лучшим аском и лучшим бидом.

1. В блоке `<div class="quote">` после строки последней сделки добавьте строку спреда:

   ```html
   <span class="label">Спред</span><span id="spread">—</span>
   ```

2. В функции `follow()` замените массив `stops` целиком. Первая подписка в нём — на стакан `book`; к
   отрисовке бида и аска она добавляет спред:

   <!-- check: prelude const exchange = "BinanceSpot"; const symbol = "BTCUSDT"; let stops = []; const $ = (id) => document.getElementById(id); function paintBook(book) {} -->
   ```js
   stops = [
     stream.subscribe("book", { exchange, symbol, depth: 1, hz: 4 }, (book) => {
       paintBook(book);
       // Цены приходят десятичными строками: спред считаем в числах и округляем до шага цены.
       const digits = (book.tickSize.split(".")[1] ?? "").length;
       const spread = Number(book.bestAsk) - Number(book.bestBid);
       $("spread").textContent = book.bestBid && book.bestAsk ? spread.toFixed(digits) : "—";
     }),
     stream.subscribe("trades", { exchange, symbol }, (frame) => {
       const print = frame.trades[frame.trades.length - 1];
       if (!print) return;
       $("last").textContent = print.price;
       $("last").className = print.isBuy ? "buy" : "sell";
     }),
   ];
   ```

3. Сохраните файл. Через полсекунды-секунду виджет перезагрузится сам, и под сделкой появится спред.

Вторую подписку на тот же стакан не заводите: на одну биржу и монету у канала одна подписка, а
обработчик получает каждый снимок своего канала. Внутри обработчика `book` типизирован как `Book` из
`colibri.d.ts`, поэтому VS Code подскажет его поля. Перезагрузка открывает страницу заново: всё, что
было в памяти, теряется, а выбранный рынок шаблон хранит в `storage` и восстанавливает.

Если спред не появился, откройте DevTools виджета — консоль, сеть и элементы Chromium, как в
браузере:

- в окне виджета — ⚙ (**«Меню виджета»**) → **«DevTools»**;
- в блоке — ⚙ в заголовке виджета → **«DevTools»**;
- в Nest → **«Мои виджеты»** → ⋯ в строке виджета → **«DevTools»**.

Горячую перезагрузку можно выключить переключателем **«Горячая перезагрузка»** в разделе **«Код»** и
перезагружать виджет вручную кнопкой **«Перезагрузить»** рядом.

## <a id="permissions"></a>7. Разрешения

`permissions` в `widget.json` — это то, на что терминал спрашивает согласие пользователя. Добавьте
разрешение — и после сохранения виджет остановится на карточке **«Нужны разрешения»**: нажмите
**«Разрешения…»** и согласитесь заново. У пользователей будет так же: версия с новым разрешением
спросит каждого заново при обновлении, а Nest всегда отдаёт такую версию на проверку модератору.

Просите минимум. Каждая строка в окне согласия — повод не устанавливать виджет, а лишнее разрешение
— причина отклонить версию. Простому шаблону хватает `marketData` и `storage`, в этом руководстве
ничего добавлять не нужно. Все разрешения и что они открывают — в
[reference/README.md#permissions](reference/README.md#permissions).

## <a id="listing"></a>8. Листинг

Листинг — то, как виджет выглядит в каталоге и на своей странице в Nest. Откройте **«Обзор»**: в
карточке **«Готовность к первой версии»** пять обязательных пунктов — **«Название»**, **«Иконка»**,
**«Категория»**, **«Описание (RU или EN)»** и **«Код связан»**. Название и код уже есть. Остальное —
в разделе **«Листинг»**:

1. **«Иконка»** → **«Выбрать иконку…»**. PNG, JPEG, WebP, GIF, BMP или ICO до 512 КБ, каждая сторона
   от 32 до 1024 px; лучше всего квадрат 128×128 на прозрачном фоне. SVG не подходит. Иконка
   сохраняется сразу.
2. **«Категория»** — например, **«Рыночные данные»**.
3. **«Описание (RU)»** и **«Описание (EN)»** — короткая строка в каталоге, до 400 знаков. Нужно хотя
   бы одно.
4. Нажмите **«Сохранить»**.

Справа, под **«В каталоге»**, строка каталога меняется по мере ввода. В разделе **«Обзор»**
готовность станет 5 / 5, а карточка **«ЧТО ДАЛЬШЕ»** скажет **«Готов к первой версии»**. Пункты с
пометкой **«рекомендуется»** — подробное описание, скриншоты, ссылки — выпуск не задерживают. Все
поля листинга — [publishing.md#listing](publishing.md#listing).

## <a id="first-release"></a>9. Первая версия — только по ссылке

В этом руководстве версия 1.0.0 выходит только по ссылке: учебному виджету не место в общем
каталоге, а каталог вы попросите следующей версией.

Нажмите **«Выпустить первую версию»** в заголовке страницы. Откроется мастер выпуска из четырёх
шагов:

1. **«1 · Версия»**. В `widget.json` шаблона уже стоит `1.0.0`, и мастер предлагает именно его —
   **«как в widget.json»**. Нажмите **«Далее»**.
2. **«2 · Что нового»**. Для первой версии — по желанию. Например, в **«Что нового — по-русски»**:
   «Бид, аск, последняя сделка и спред», в **«Что нового — по-английски»** — то же по-английски.
3. **«3 · Сборка»**. После **«Собираем архив…»** мастер покажет номер с пометкой
   **«вписана в widget.json»**, **«Размер»** и **«SHA-256»** архива, а в
   **«Что изменится для пользователей»** — что первую версию модератор проверяет вместе с листингом.
   В архив уходит вся папка `widget/`.
4. **«4 · Отправка»**. В **«Где предлагать»** выберите **«Только по ссылке»** и нажмите
   **«Отправить на проверку»**.

Мастер закроется на разделе **«Версии»**. Строка 1.0.0 сначала в состоянии **«Проверяется»** — Nest
проверяет архив автоматически, обычно минуту-две. Затем **«На проверке»**: версию и листинг смотрит
модератор, рядом — к какому сроку он обычно отвечает. Решение придёт в **«Уведомления»**
(колокольчик в строке автора), а строка станет **«Текущая»**.

Если что-то не так:

- **«Не прошла проверки»** — архив не прошёл автоматическую проверку. Раскройте строку: там этап,
  что исправить и **«Подробнее о правиле»**. Версия не сохранилась, поэтому после исправления можно
  снова отправить 1.0.0.
- **«Отклонена»** — модератор отклонил версию и написал почему. Ответить можно в переписке по этой
  версии; исправленный код уходит следующим номером.

Все этапы проверки и что значит каждый отказ — [publishing.md#review](publishing.md#review).

## <a id="install-link"></a>10. Ссылка для установки

Откройте **«Доступ»** → **«Ссылка для установки»** и нажмите **«Копировать»** (или
**«Скопировать ссылку»** в заголовке страницы). Ссылка появляется после первой отправки и работает,
как только первую версию одобрили.

По ссылке виджет может установить любой, у кого она есть: в Nest → **«Мои виджеты»** →
**«Добавить локальный виджет…»** вставить её в поле и нажать **«Продолжить»**. Дальше — обычная
установка: окно согласия, закреплённый хеш, отзыв прав в один клик. Поэтому ссылку отдавайте только
тем, кому хотите.

## <a id="catalog"></a>11. Версия 1.0.1 — в каталог

Исправьте что-нибудь в `widget/index.html`, сохраните и проверьте в окне виджета. Затем
**«Выпустить версию»**:

1. **«1 · Версия»** — первым мастер предлагает **«исправление»**, `1.0.1`. Номера только растут:
   1.0.0 уже занят навсегда.
2. **«2 · Что нового»** — теперь обязательно хотя бы на одном языке: пользователи видят это перед
   обновлением.
3. **«3 · Сборка»** — меняется только код, пользователей ни о чём заново не спросят.
4. **«4 · Отправка»** — у **«Только по ссылке»** пометка **«сейчас»**. Выберите **«В каталоге»**:
   это запрос, модератор решит его вместе с версией 1.0.1. Нажмите **«Отправить на проверку»**.

В заголовке страницы появится **«Запрошен каталог»**. Модератор может одобрить версию и взять виджет
в каталог — тогда его найдут все, а раздел **«Обзор»** скажет «В каталоге · версия 1.0.1». Может
одобрить версию, но в каталог не взять, — тогда виджет остаётся по ссылке, а причина придёт в
**«Уведомления»**. Чем каталог отличается от ссылки — в
[publishing.md#catalog-or-link](publishing.md#catalog-or-link).

## <a id="other-paths"></a>Другие пути к коду

### <a id="own-folder"></a>Своя папка

**«Код»** → **«Папка с проектом»** → **«Выбрать папку…»**. Подойдёт любая папка, в которой лежит
`widget.json`. Самая маленькая — два файла, `widget.json` и `index.html`:

```json
{
  "id": "my-widget",
  "version": "1.0.0",
  "entry": "index.html",
  "surfaces": ["slot", "window"],
  "permissions": ["marketData"]
}
```

Черновик берёт ID из этого `widget.json`. Если у черновика ещё нет ID, он берёт его сразу; если ID
уже есть, а версий нет, терминал спросит, сменить ли его, — **«Сменить ID»**, и прежний ID
освободится. У виджета с версией ID уже не меняется: папка должна нести его ID, иначе терминал
скажет, какой нужен. Папку, которая принадлежит другому вашему виджету, связать нельзя. То же в один
шаг: **«Новый виджет»** → **«Взять из папки…»** — название и ID возьмутся из `widget.json`, а папка
свяжется сразу после создания.

Терминал отдаёт папку на месте — ничего не копирует — и перезагружает виджет после каждого
сохранения. Ваши файлы он сам не меняет. Исключение одно: мастер выпуска вписывает номер версии в
`widget.json` и возвращает прежний, если выпуск отменить. Связывайте папку с готовым виджетом
(`dist/`, если есть сборка), а не корень проекта с `node_modules`: версия ограничена 2000 файлами и
50 МБ.

### <a id="hosted"></a>Сайт, который уже работает

**«Код»** → **«Адрес сайта (hosted)»** → **«Указать адрес»**. Заполните **«Адрес»** (https://…),
**«ID»** (предложен по названию) и **«Где показывать»** — слот, окно или оба, затем нажмите
**«Связать»**. Терминал сам соберёт `widget.json` и откроет ваш сайт как виджет.

Сначала манифест минимальный: ни одного разрешения и только хост самого сайта. Откройте виджет и
пройдите по его функциям — всё, в чём терминал сайту отказал, появится в разделе **«Код»** под
**«Сайт пытался — и получил отказ»**: **«Добавить»** по одному или **«Добавить все»**. Остальное —
**«Указать вручную»**.

Мастер выпуска у такого виджета — три шага, без сборки. Сам сайт вы обновляете без выпуска, а каждую
hosted-версию проверяет модератор. Когда выбирать hosted, а когда bundled, —
[publishing.md#hosted](publishing.md#hosted).

### <a id="react"></a>Шаблон на TypeScript и React

В **«Новый проект из шаблона»** выберите **«TypeScript + React»** — плитку с пометкой **«Node.js»**.
Терминал загрузит готовую сборку `dist/` из шаблона, поэтому виджет работает сразу, без Node.js.

Чтобы править код, нужен Node.js 20 или новее. В разделе **«Код»** появится
**«Дальше: править исходники»** — две команды, которые нужно выполнить в папке проекта
(**«Открыть папку проекта»**):

```bash
npm install
npm run watch
```

`npm run watch` — это `vite build --watch`: он переписывает `dist/` на каждое сохранение, а терминал
перезагружает виджет. Правьте `src/App.tsx`; типы проверяет `npm run typecheck`. Подробнее —
[starters/react/README.md](../starters/react/README.md).

Привычнее HMR? Запустите `npm run dev` (Vite на `localhost:5173`) и свяжите вместо `dist/` папку
`dev/` — **«Связать другую папку…»**. В её `widget.json` `entry` указывает на dev-сервер; так можно
только в связанной папке для разработки — см.
[reference/manifest.md#dev-server-entry](reference/manifest.md#dev-server-entry). Выпустить такую
папку нельзя: перед **«Выпустить версию»** свяжите `dist/` обратно.

Мастер выпуска пакует связанную `dist/`. Новый номер он вписывает в `dist/widget.json`, а заодно в
`public/widget.json` и `dev/widget.json`, чтобы следующая сборка его не потеряла, — только в те
копии, где стоит ID этого виджета и прежний номер. Отменили выпуск — прежний номер вернётся во все
три.
