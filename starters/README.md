# Шаблоны виджетов

Из этих четырёх проектов терминал создаёт виджет сам: **Nest → «Автор» → виджет → «Код» → «Из
шаблона»**. Автор выбирает шаблон и папку; терминал скачивает шаблон из релиза этого репозитория,
сверяет SHA-256, вписывает ID виджета во все `widget.json` (и имя в `package.json`), создаёт папку
`<папка>\<ID>` и загружает её с горячей перезагрузкой.

> English — [README.en.md](README.en.md).

| Шаблон | Папка | Сборка | Терминал загружает | Разрешения |
|---|---|---|---|---|
| Простой | [`plain/`](plain/) | нет | `widget/` | marketData, storage |
| TypeScript + React | [`react/`](react/) | Vite | `dist/` | marketData, storage |
| Торговый | [`trading/`](trading/) | Vite | `dist/` | marketData, account:read, trading, storage |
| График | [`chart/`](chart/) | нет | `widget/` | marketData, storage |

Терминал всегда загружает **подпапку**, а не корень проекта: в корне лежат README, `node_modules`
и `.git`, а терминал хеширует и отслеживает всё, что загружает. В шаблоне на Vite готовая сборка
`dist/` уже лежит в архиве, поэтому он работает сразу, без Node.js; Node.js 20+ нужен, чтобы
править код.

## Для тех, кто меняет шаблоны

Опись шаблонов — [`starters.json`](starters.json). На каждый шаблон:

| Поле | Что это |
|---|---|
| `key` | имя шаблона: `^[a-z0-9][a-z0-9-]{0,31}$`; архив называется `starter-<key>.zip` |
| `title`, `description` | плитка в терминале, `ru` и `en` |
| `path` | папка шаблона в этом репозитории |
| `build` | `"vite"` — CI выполняет `npm ci`, `npm run typecheck`, `npm run build`; `null` — без сборки |
| `serve` | подпапка, которую терминал связывает с виджетом |
| `manifests` | каждый `widget.json`, в который терминал впишет ID; обязательно `<serve>/widget.json` |
| `packageJson` | куда вписать ID как имя пакета, или `null` |
| `edit` | файл, который терминал предложит открыть первым |

Правила, которые проверяет CI (`node scripts/starters.mjs check`):

- все манифесты одного шаблона совпадают по `id`, `version` и `permissions`;
- в манифесте нет `name`, `icon` и `author` — их задают в Nest;
- у загружаемого манифеста `entry` — относительный путь; адрес dev-сервера
  (`http://localhost:…`) допустим только в `dev/widget.json`;
- каждая копия `colibri.js` и `colibri.d.ts` совпадает с [`sdk/`](../sdk/) байт в байт:
  `node scripts/sync-sdk-copies.mjs` перепишет их, `--check` проверит.

И правила, которые не проверить скриптом:

- цвета — только `var(--colibri-role-*)` с запасным значением: так виджет следует теме терминала;
- никаких `eval`, `new Function` и `document.write`: Nest отклоняет такой код при проверке;
- текст на экране — на языке терминала (`handshake().lang`, событие `theme`), ru и en;
- торговый шаблон отправляет заявку **только** по нажатию «Подтвердить»: никогда при открытии, по
  таймеру, из обработчика потока, из сохранённых настроек или по клавише. Цена и объём не
  восстанавливаются из `storage`.

### Выпуск

Каждый релиз этого репозитория — релиз шаблонов: терминалы читают
`releases/latest/download/starters.json`. Чтобы выпустить изменения, слейте их и отправьте тег
`starters-X.Y.Z`. Workflow `starters.yml` соберёт и упакует шаблоны, опубликует релиз черновиком
(черновик не виден как `latest`, пока не загружены все архивы), отметит его последним и скачает
обратно, сверив каждый хеш.

Терминал строит адрес архива сам: `releases/download/<release>/<asset>`, где `release` взят из той
же описи. Поэтому опись и архивы не могут прийти из разных релизов.

### Формат описи меняется только добавлением

Опубликованный `starters.json` несёт `schemaVersion: 1`. Внутри первой версии поля только
добавляются, необязательными; терминал пропускает поля, которых не знает. Ломающее изменение
публикует `starters.v2.json` рядом, а `starters.json` продолжает выходить для терминалов, которые
читают первую версию. Терминал, получивший `schemaVersion` новее своей, просит обновиться.
