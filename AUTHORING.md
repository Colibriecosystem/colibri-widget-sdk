# Путь автора виджета: три стадии

> English version — [AUTHORING.en.md](AUTHORING.en.md).

Виджет проходит три стадии — от папки на вашей машине до общего каталога. Все три собраны в одном
месте: **Nest → «Мои виджеты» → «Добавить виджет…»**. Диалог показывает стадии как три карточки;
эта страница — подробная версия каждой из них.

| Стадия | Что это | Целостность | DevTools |
| --- | --- | --- | --- |
| 1 · Разработка | ваша папка обслуживается на месте | хеш перезаписывается при каждой загрузке | всегда |
| 2 · Локальная установка | полноценная Prod-установка, только на этой машине | хеш зафиксирован при установке | по настройке |
| 3 · Публикация | общий каталог сообщества (следующая бета) | хеш утверждает реестр | — |

---

## Стадия 1 · Разработка

Кнопка **«Загрузить распакованный…»** обслуживает вашу папку **на месте** — ничего не копируется.
DevTools доступны всегда, логи полные, а переключатель **«Горячая перезагрузка»** пересобирает виджет
примерно через полсекунды после каждого сохранения (всплеск сохранений схлопывается в одну
перезагрузку). Кнопка **«Перезагрузить»** делает то же самое вручную. Всё работает внутри
терминала — браузер не нужен, если вы так хотите: DevTools открываются прямо из меню виджета.

Минимальная папка — два файла:

```
my-widget/
├─ widget.json
└─ index.html
```

```json
{
  "id": "my-widget",
  "name": "Мой виджет",
  "version": "0.1.0",
  "entry": "index.html",
  "surfaces": ["slot", "window"],
  "permissions": ["storage"]
}
```

`id` — это одновременно имя папки установки и метка виртуального хоста, поэтому он строго
lowercase DNS-label (`a–z`, `0–9`, дефисы). `entry` — путь внутри папки. Полный стартовый проект
(TS + React, без привязки к фреймворку) лежит в [`template/`](template/).

Необязательное поле `icon` — путь к картинке внутри бандла (PNG, до 512 КБ): терминал показывает
её везде, где виджет виден — карточка каталога и листинг, список «Мои виджеты», вкладка «Виджеты»
в окне уведомлений, закладка в нижней строке, заголовок панели и окна, меню 🧩. Без иконки везде
рисуется значок 🧩. И про `surfaces`: только виджет, объявивший `"window"`, открывается отдельным
окном и может быть закреплён закладкой в нижней строке — slot-only виджет живёт только в панелях.

Один режим доступен только здесь: `entry` может указывать на dev-сервер
(`http://localhost:5173/`) — так работает HMR Vite. Обычная установка такой манифест отвергнет;
это осознанное послабление именно для распакованного режима.

Каждая перезагрузка в этом режиме **перефиксирует** хеш содержимого: вы меняете код — терминал
принимает новую версию как вашу. Это и есть отличие от Prod-режима, где изменившийся байт —
причина отказаться запускаться.

## Стадия 2 · Локальная установка

Всё то же, что у «настоящего» виджета из каталога — хеш содержимого зафиксирован при установке,
разрешения выданы через диалог согласия, переключатель включения, отзыв прав в один клик — но
доступно только на этой машине. Три способа попасть сюда, все из того же диалога:

### Из zip-архива

На карточке вашего распакованного виджета есть кнопка **«Упаковать для Nest»** — она собирает
архив так, что заявленный хеш воспроизводится **распаковкой и повторным хешированием содержимого**
(именно так его проверит и CI реестра). Полученный файл ставится кнопкой
**«Установить из zip…»** — защита от zip-slip, лимиты на распакованный размер
(2000 файлов / 20 МБ на файл / 50 МБ всего), временная папка всегда удаляется.

### По ссылке на .zip

В поле «Из интернета» вставьте https-ссылку, оканчивающуюся на `.zip`, и нажмите
**«Продолжить»** — терминал скачает архив по собственной цепочке маршрутов (прямое соединение,
затем ваши прокси; предел 64 МБ на принятые байты) и проведёт его через тот же zip-путь: то же
согласие, тот же хеш из распакованного содержимого.

### Работающее веб-приложение — просто URL, без папки

Если ссылка не оканчивается на `.zip`, диалог разворачивает форму: **Название**, **ID**
(выводится из названия автоматически, можно править), **Версия**, **Поверхности**
(slot / window), **Разрешения** (те же семь, что видит пользователь в диалоге согласия) и
**«Дополнительные сетевые хосты»**. Хост самой ссылки попадает в `egress` всегда — его вписывать
не нужно.

Терминал сам чеканит одностраничный `widget.json` и ставит его как hosted-виджет. Например, форма

- URL: `https://screener.example.com/app/`
- Название: `My Screener` · Версия: `1.0.0`
- Разрешения: уведомления, своё хранилище
- Дополнительные хосты: `api.example.com`

превращается ровно в такой манифест:

```json
{
  "id": "my-screener",
  "name": "My Screener",
  "version": "1.0.0",
  "entry": "https://screener.example.com/app/",
  "surfaces": ["slot", "window"],
  "permissions": ["notifications", "storage"],
  "egress": ["screener.example.com", "api.example.com"]
}
```

Честное отличие hosted-режима: идентичность здесь — **origin, а не хеш содержимого**. Что бы этот
URL ни отдал завтра, то и выполнится — поэтому карточка носит янтарную метку `hosted` вместо
зелёной `bundled · hash ✓`.

## Стадия 3 · Публикация

Одна заявка — и любой пользователь увидит ваш виджет в каталоге и установит его в один клик.
Всё происходит внутри терминала: **Nest → Добавить виджет → «Публикация»**.

1. **Вход.** Кнопка открывает страницу GitHub с коротким кодом. Пароль вы нигде не вводите:
   реестр сам ведёт device flow, токен GitHub до вашей машины не доходит, а терминал получает
   собственный ключ реестра — он умеет ровно одно, отправлять заявки от вашего имени.
2. **Архив** — та же кнопка «Упаковать для Nest». Её контракт (хеш воспроизводится из
   распакованного содержимого) и есть то, что проверяет реестр.
3. **Карточка** — то, что вы заполняете в форме. Важно различать две оси:
   **категория** — ключ из нашего списка, одна на виджет, выбирается при подаче заявки;
   **теги** — ваши собственные, про возможности виджета, сколько угодно, показываются как есть.

```json
{
  "id": "my-screener",
  "category": "analytics",
  "tags": ["screener", "funding"],
  "descriptionEn": "Cross-venue screener with funding extremes.",
  "descriptionRu": "Скринер по биржам с экстремумами фандинга."
}
```

Карточка не может завысить или занизить права: всё, что касается безопасности — имя, версия,
поверхности, разрешения, сетевые хосты — берётся из манифеста самого архива, **тем же кодом,
которым это проверяет десктоп**. Форма спрашивает только оформление (описания, категория, теги) —
поэтому в ней и нет ни одного поля про безопасность.

После загрузки проверки идут на сервере, а окно показывает их по одной. Отказ называет конкретную
проверку — это ваш диагноз, а не «заявка отклонена».

Перед первой заявкой прочитайте [policies/CONTENT.md](policies/CONTENT.md): что можно публиковать,
и почему просить лишнее право — плохая идея. Что бывает, если виджет снимают с публикации:
[policies/TAKEDOWN.md](policies/TAKEDOWN.md).
