# Путь автора виджета

> English version — [AUTHORING.en.md](AUTHORING.en.md).

В терминале у автора два места:

- **Nest → «Автор»** — всё, что касается ваших виджетов: профиль и ID автора, страница каждого
  виджета, связь с папкой проекта (разработка с горячей перезагрузкой), выпуск версий, проверка,
  каталог или ссылка.
- **Nest → «Мои виджеты» → «Добавить локальный виджет…»** — установка только на этой машине: zip,
  ссылка на .zip, ссылка на виджет «только по ссылке» или работающее веб-приложение по URL.

| Режим | Где | Целостность | DevTools |
| --- | --- | --- | --- |
| Разработка | «Автор» → виджет → «Код» | хеш перефиксируется при каждой перезагрузке | всегда |
| Локальная установка | «Мои виджеты» → «Добавить локальный виджет…» | хеш зафиксирован при установке | по настройке |
| Публикация | «Автор» → виджет → «Выпустить версию» | хеш утверждает реестр | — |

> В предыдущих версиях терминала всё это было в одном диалоге «Добавить виджет…» — с карточками
> «Разработка» и «Публикация» и кнопкой «Упаковать для Nest» на строке виджета. В новых версиях их
> нет: разработка и публикация переехали на вкладку «Автор».

---

## Сначала развилка: hosted или bundled

Если у вас **уже есть работающее веб-приложение на своём https-домене** — берите hosted. `entry`
указывает на ваш URL, папка состоит из одного `widget.json`, собирать и упаковывать нечего, а
обновления вы выкатываете со своего сервера, не переиздавая виджет. Авторы с готовым сайтом чаще
всего всё равно собирают бандл — это лишняя работа, которая в их случае почти ничего не добавляет.

| | Hosted (`entry` — ваш https-URL) | Bundled (`entry` — файл в папке) |
| --- | --- | --- |
| Что нужно | работающий сайт | сборка проекта |
| Обновления | выкатываете у себя на сервере | новая версия |
| Каталог Nest, консент, отзыв прав, тема, установка в один клик | да | да |
| Метка в каталоге | янтарная `hosted` | зелёная `в пакете · хеш ✓` |
| Работает без вашего сервера | нет | да |
| Проверка модератором | всегда вручную: hosted не автоодобряется | обновления доверенного издателя могут автоодобряться |

**Не заворачивайте свой сайт в бандл.** Бандл, вся точка входа которого — `<iframe>` на ваш
сайт, — это hosted в чужой одежде: реестр это распознаёт отдельной проверкой (`embed`), карточка
всё равно получает янтарную метку с именем встраиваемого сайта, а если такой виджет просит
`trading` или `account:read`, заявка **отклоняется автоматически**. Зелёную метку даёт только код,
который действительно лежит в архиве: хеш покрывает то, что приехало в zip, а не то, что ваш
сервер отдаст завтра.

Архитектурная сторона выбора — в [CAPABILITIES.md](CAPABILITIES.md), раздел «Как выбрать
архитектуру».

## Стать автором

**Nest → «Автор» → «Стать автором».** Входа и пароля нет. Укажите **имя в каталоге** (его видят
пользователи) и **почту** (её видит только Colibri — чтобы связаться с вами по поводу виджетов);
ссылки на YouTube, Telegram и исходный код необязательны и меняются позже. Нажмите
**«Создать ID автора»** — Nest выдаст вам ID, и терминал покажет его на карточке, пока вы не нажмёте
**«Я сохранил ключ»**.

**Скопируйте ID и сохраните в надёжном месте.** По нему реестр понимает, что виджеты ваши: он не
даёт никому другому их обновить — и ровно так же позволяет действовать от вашего имени тому, у кого
он окажется. Выдаётся он один раз и повторно выдан быть не может, восстановления пока нет: при
потере обновить свои виджеты вы не сможете — напишите нам, разберёмся вручную. На другой машине
вставьте его в поле **«У меня уже есть ID автора»**.

## Новый виджет

**«Новый виджет»** спрашивает только название; ID виджета выдаёт Nest. Категорию и описание можно
заполнить сразу или позже — до первой версии. Откроется страница виджета: **«Обзор»** с одним
следующим шагом и списком того, чего не хватает до первой версии, и разделы **«Версии»**,
**«Листинг»**, **«Код»**, **«Доступ»**, **«Статистика»**.

## Разработка: папка проекта

**«Код» → «Выбрать папку…».** Терминал впишет ID виджета в `widget.json` выбранной папки (сначала
покажет старый и новый ID — меняется только поле `id`, остальное в файле не трогается) и будет
обслуживать папку **на месте** — ничего не копируется. Папка, которая уже принадлежит другому
вашему виджету, не подойдёт.

DevTools доступны всегда, логи полные, а переключатель **«Горячая перезагрузка»** пересобирает
виджет примерно через полсекунды после каждого сохранения (всплеск сохранений схлопывается в одну
перезагрузку). Кнопка **«Перезагрузить»** делает то же самое вручную. Всё работает внутри
терминала — браузер не нужен, если вы так хотите: DevTools открываются прямо из меню виджета.

Минимальная папка — два файла:

```
my-widget/
├─ widget.json
└─ index.html
```

```json
{
  "id": "my-widget",
  "name": "Мой виджет",
  "version": "0.1.0",
  "entry": "index.html",
  "surfaces": ["slot", "window"],
  "permissions": ["storage"]
}
```

`id` — это одновременно имя папки установки и метка виртуального хоста, поэтому он строго
lowercase DNS-label (`a–z`, `0–9`, дефисы). При связывании терминал заменит его на ID, выданный
Nest, — до этого можно указать любой. Если `widget.json` в вывод кладёт сборка, впишите ID виджета (кнопка копирования рядом с ним на странице виджета) и в исходный файл — иначе следующая сборка вернёт старый ID, и терминал откажется выпускать эту папку. `entry` — путь внутри папки. Полный стартовый проект
(TS + React, без привязки к фреймворку) лежит в [`template/`](template/).

Необязательное поле `icon` — путь к картинке **внутри бандла** (URL указать нельзя): терминал
показывает её везде, где виджет виден — карточка каталога и листинг, список «Мои виджеты»,
вкладка «Виджеты» в окне уведомлений, закладка в нижней строке, заголовок панели и окна, меню 🧩.
Без иконки везде рисуется значок 🧩. Иконку в каталоге можно задать и отдельно — в разделе
«Листинг».

- **Формат** — PNG (JPEG и WEBP тоже читаются); **SVG не поддерживается**.
- **Вес файла** — до 512 КБ.
- **Размер картинки** — 128×128, квадрат, прозрачный фон: крупнее всего иконка рисуется 44×44 в
  шапке листинга, в списках — 22–26 px.
- **Ошибки молчаливые.** Неверный путь, слишком тяжёлый файл, формат, который не читается, — всё
  это просто оставляет значок 🧩, без единого сообщения. Если иконка «не появилась», проверяйте
  сначала путь и вес файла.

И про `surfaces`: только виджет, объявивший `"window"`, открывается отдельным окном и может быть
закреплён закладкой в нижней строке — slot-only виджет живёт только в панелях.

Один режим доступен только для связанной папки: `entry` может указывать на dev-сервер
(`http://localhost:5173/`) — так работает HMR Vite. Обычная установка такой манифест отвергнет;
это осознанное послабление именно для режима разработки. HMR-сокет держите на порту самой записи
`entry`: `connect-src` страницы называет ваш dev-origin именно с этим портом, и больше ничего на
loopback.

Каждая перезагрузка в этом режиме **перефиксирует** хеш содержимого: вы меняете код — терминал
принимает новую версию как вашу. Это и есть отличие от Prod-режима, где изменившийся байт —
причина отказаться запускаться.

## Листинг

Раздел **«Листинг»** — то, как виджет выглядит в каталоге: название, иконка, категория, теги,
описания на русском и английском. Справа — строка каталога в том виде, в каком её увидят
пользователи, обновляется по мере ввода. Правки сохраняются сразу, без новой версии; только новое
название и новая иконка виджета, который уже в каталоге, ждут модератора.

Две оси, которые важно различать: **категория** — ключ из нашего списка, одна на виджет; **теги** —
ваши собственные, про возможности виджета, сколько угодно, показываются как есть.

Листинг не может завысить или занизить права: всё, что касается безопасности — имя, версия,
поверхности, разрешения, сетевые хосты, — берётся из манифеста самого архива, **тем же кодом,
которым это проверяет десктоп**. Поэтому в листинге нет ни одного поля про безопасность.

## Выпуск версии

**«Выпустить версию»** (у нового виджета — «Выпустить первую версию») открывает мастер из четырёх
шагов:

1. **Версия.** Мастер предлагает номер после наибольшего, который когда-либо был у виджета:
   исправление, новые возможности или несовместимые изменения — или свой, если он идёт после
   наибольшего. Использованный номер не переиспользуется, даже если ту версию отклонили или вы её
   отозвали. Номер впишется в `widget.json` при сборке архива и вернётся обратно, если отменить.
2. **«Что нового».** На русском и английском, до 1000 символов каждое. Для обновления обязательно
   хотя бы на одном языке: пользователи видят это перед обновлением. Для первой версии — по
   желанию. Если у нового виджета нет категории или описания, мастер остановится здесь и отправит
   вас в «Листинг»: без них первая версия не пройдёт проверку.
3. **Сборка.** Терминал собирает архив из связанной папки так, что хеш воспроизводится
   **распаковкой и повторным хешированием содержимого** (именно так его проверяет реестр), и
   показывает размер, хеш и **что изменится для пользователей**: новые и убранные разрешения,
   сетевые адреса, места, где открывается виджет. Новое разрешение или новый хост — это повод
   спросить пользователей заново при обновлении, и такую версию проверит модератор. Если меняется
   только код, так и написано.
4. **Отправка — и где предлагать.** **«В каталоге»** или **«Только по ссылке»**, на каждом выпуске.
   Первая версия по умолчанию идёт в каталог: модератор проверяет её вместе с листингом, и после
   одобрения виджет появляется в каталоге для всех. Обновление начинает с того, где виджет сейчас
   (пометка «сейчас»): переход в каталог — это запрос, который модератор решает вместе с этой
   версией; уход из каталога происходит, как только версия пройдёт автоматические проверки, без
   модератора, а установленные копии продолжают работать. **«Отправить на проверку»** — и мастер
   закроется на разделе «Версии».

### После отправки

Раздел **«Версии»** — история всех версий: состояние, когда отправлена и когда решена, «Что нового»
и что изменилось для пользователей. Проверки идут на сервере; отказ называет конкретную проверку и
её код, а терминал рядом показывает, что исправить, и ссылку на правило — это ваш диагноз, а не
«заявка отклонена». Все коды и что с ними делать: [CHECKS.md](CHECKS.md). Версия, которая ждёт
человека, показывает, к какому сроку обычно отвечает модератор; если он отклонил версию — причину,
комментарий и переписку по ней. Исправили код — **«Отправить новую версию…»** откроет тот же
мастер.

- **«Изменить «Что нового»»** — текст правится без новой версии и без проверки.
- **«Отозвать»** — версию, которая ещё ждёт проверки, можно снять с проверки. Её номер останется
  занятым, следующая версия получит больший.

Раздел **«Доступ»** — **ссылка для установки** (появляется после первой отправки и работает после
одобрения первой версии; по ней виджет может установить любой, в каталоге он или нет), текущая
видимость, **«Снять»** / **«Вернуть»** и **«Удалить»** — последнее только для черновика, который
ни разу не одобряли.

Перед первой версией прочитайте [policies/CONTENT.md](policies/CONTENT.md): что можно публиковать,
и почему просить лишнее право — плохая идея. Что бывает, если виджет снимают с публикации:
[policies/TAKEDOWN.md](policies/TAKEDOWN.md).

## Локальная установка

Всё то же, что у «настоящего» виджета из каталога — хеш содержимого зафиксирован при установке,
разрешения выданы через диалог согласия, переключатель включения, отзыв прав в один клик — но
доступно только на этой машине. Всё — из одного диалога: **Nest → «Мои виджеты» →
«Добавить локальный виджет…»**.

### Из zip-архива

Кнопка **«Установить из zip…»** ставит архив, в корне которого лежит `widget.json`: защита от
zip-slip, лимиты на распакованный размер (2000 файлов / 20 МБ на файл / 50 МБ всего), временная
папка всегда удаляется. Хеш считается по распакованному содержимому, поэтому архив, собранный любым
zip-инструментом, даёт тот же хеш.

### По ссылке на .zip

В поле «Из интернета» вставьте https-ссылку, оканчивающуюся на `.zip`, и нажмите
**«Продолжить»** — терминал скачает архив по собственной цепочке маршрутов (прямое соединение,
затем ваши прокси; предел 64 МБ на принятые байты) и проведёт его через тот же zip-путь: то же
согласие, тот же хеш из распакованного содержимого.

### По ссылке на виджет «только по ссылке»

Автор виджета, который не в каталоге, даёт ссылку для установки. Вставьте её в то же поле —
терминал установит виджет из Nest.

### Работающее веб-приложение — просто URL, без папки

Если ссылка не оканчивается на `.zip`, диалог разворачивает форму: **Название**, **ID**
(выводится из названия автоматически, можно править), **Версия**, **Поверхности**
(slot / window), **Разрешения** (те же семь, что видит пользователь в диалоге согласия) и
**«Дополнительные сетевые хосты»**. Хост самой ссылки попадает в `egress` всегда — его вписывать
не нужно.

Терминал сам чеканит одностраничный `widget.json` и ставит его как hosted-виджет. Например, форма

- URL: `https://screener.example.com/app/`
- Название: `My Screener` · Версия: `1.0.0`
- Разрешения: уведомления, своё хранилище
- Дополнительные хосты: `api.example.com`

превращается ровно в такой манифест:

```json
{
  "id": "my-screener",
  "name": "My Screener",
  "version": "1.0.0",
  "entry": "https://screener.example.com/app/",
  "surfaces": ["slot", "window"],
  "permissions": ["notifications", "storage"],
  "egress": ["screener.example.com", "api.example.com"]
}
```

Честное отличие hosted-режима: идентичность здесь — **origin, а не хеш содержимого**. Что бы этот
URL ни отдал завтра, то и выполнится — поэтому карточка носит янтарную метку `hosted` вместо
зелёной `bundled · hash ✓`.

**Логотип и публикация hosted-виджета.** Форма по URL чеканит `widget.json` из одного файла, и
поля `icon` в ней нет: такой виджет остаётся со значком 🧩 везде и в каталог не попадает. Если
hosted-виджету нужен свой логотип или место в каталоге, соберите папку руками — это два файла:

```
my-widget/
├─ widget.json   ← entry: "https://ваш-домен/app/"
└─ icon.png
```

создайте виджет на вкладке «Автор», свяжите с ним эту папку в разделе «Код» и выпустите версию. В
архив уедут только манифест и иконка — код остаётся на вашем сервере, хеш покрывает ровно эти два
файла.
